# わが家のレシピ帖

見つけたレシピを、わが家の一冊に。

さまざまなレシピサイトの内容を統一された形式でローカルへ保存し、残り物と新しく作る料理を並べながら献立を考えるためのアプリです。

## 起動

```bash
mise install
mise exec -- pnpm install --frozen-lockfile
mise exec -- pnpm run build
mise exec -- pnpm start
```

Node.jsとpnpmのバージョンは `mise.toml` で管理します。ブラウザで <http://127.0.0.1:4310> を開きます。開発時は `mise exec -- pnpm dev` で <http://localhost:5173> を使えます。

画面の「ページを保存」は、HTMLと代表画像を `data/archives/` へ保存し、`data/archive-index.json` の取り込み待ちキューへ追加するだけです。この操作ではレシピカードを作成しません。

保存ページをカード化するときは、リポジトリ内のskillをCodexで実行します。

```text
$recipe-archive-importer 未取り込みを一括取り込み
```

skillは未処理HTMLを読み、検証できたレシピだけを `data/state.json` へ追加します。判定できないページは「要確認」に残します。`data/` フォルダ全体をバックアップすれば、原本、カード、献立をまとめて保持できます。

### 本日の献立と材料の人数換算

- 「献立を考える」は本日の献立を中心に表示します。日付欄で以前・別日の献立も開けます。
- 候補は選択済みの料理を除き、未選択の分類（主菜・副菜・汁物）を優先します。「別の候補を見る」で他の保存レシピへ切り替わります。
- レシピ詳細の「作る人数」で材料を換算します。献立に追加済みの料理では人数を保存し、詳細を再度開いた際にも反映します。
- 換算基準は保存HTML内のRecipe構造化データの明示的な人数表記から取得します。従来の `servings` は取り込み時の既定値が含まれるため、換算には使いません。
- 人数不明、単位のない数値、人数の範囲表記では自動換算しません。保存ページを確認して基準人数を設定できます。確認した基準は `servingBaseOverride` に保存し、元の材料・人数情報は保持します。
- 数値・分数・帯分数・範囲・括弧内重量を換算し、少々・適量・割合・長さ・解釈できない文章は原文のまま表示します。作り方に記載された分量と加熱時間は変えません。
- 換算テスト: `node --test tests/quantities.test.mjs`（Node.js 24）。
